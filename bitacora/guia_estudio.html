Fundamentos de Arquitectura de Software y Metodología de Datos

Un proyecto profesional de Data Science y NLP no es una colección desordenada de scripts sueltos o notebooks de Jupyter (`.ipynb`). Debe diseñarse como un sistema de software modular, reproducible y desacoplado.

1. La Metodología de Datos: Arquitectura Medallion (Multi-Hop)

En ingeniería de datos moderna (estándar en Databricks, Snowflake y Big Data), los datos nunca se sobrescriben en el mismo lugar; fluyen a través de etapas de refinamiento progresivo:

[ WEB DEL BANCO CENTRAL ] │ (Petición HTTP / Descarga) ▼ ┌──────────────────┐ │ data/raw/ │ CAPA BRONCE (Raw Storage) │ (PDFs Oficiales)│ • Datos crudos e inmutables (solo lectura). └─────────┬────────┘ • Si un algoritmo falla, siempre puedes reprocesar desde aquí sin volver a descargar. │ │ (Parsing de Layout, OCR, Tablas, Eliminación de headers/footers) ▼ ┌──────────────────┐ │ data/processed/ │ CAPA SILVER (Cleansed / Structured) │ (JSONs / Texto) │ • Texto estructurado limpio y metadatos extraídos (fechas, títulos, vigencia). └─────────┬────────┘ │ │ (Generación de Wikilinks [[...]], Frontmatter YAML de Obsidian) ▼ ┌──────────────────┐ │ data/vault/ │ CAPA GOLD (Business / Knowledge Layer) │ (Markdown .md) │ • Grafo de conocimiento navegable para humanos (Obsidian) y alimentador para el RAG. └──────────────────┘

2. Principio de Software: Separación de Responsabilidades (SoC)

El código dentro de src/ está dividido para que cada módulo tenga una única razón para cambiar (Principio de Responsabilidad Única - SRP):

  • ¿El Banco Central cambió el diseño de su página web o las URLs? Solo modificas src/connectors/. El resto del sistema ni se entera.
  • ¿Decidimos cambiar la librería de parsing de PDF (de PyMuPDF a Docling o un LLM multimodal)? Solo modificas src/parsers/. El conector y la base de datos vectorial no se tocan.
  • ¿Cambiamos de base de datos vectorial (de ChromaDB a LanceDB o Qdrant)? Solo modificas src/rag/.

3. Mapa Detallado: ¿Para qué sirve cada archivo y carpeta?

Ruta / Archivo Capa / Rol Propósito Técnico Exacto
data/raw/ Datos Crudos (Bronce) Almacena los PDFs normativos descargados intactos. Sirve como fuente de verdad auditable. Nunca se modifica manualmente.
data/processed/ Datos Procesados (Plata) Almacena salidas intermedias de algoritmos: chunks estructurados en formato JSON, textos tokenizados o tablas extraídas en CSV.
data/vault/ Base de Conocimiento (Oro) Es el directorio que se abre directamente como una "Bóveda" en Obsidian. Contiene los archivos .md con metadatos y enlaces cruzados.
src/connectors/ Capa de Ingesta (I/O) Módulos Python encargados del scraping, peticiones HTTP, manejo de cookies, reintentos de red y descarga de documentos normativos.
src/parsers/ Capa de Transformación Algoritmos de NLP y extracción documental: detecta artículos, capítulos, incisos, elimina encabezados de página repetitivos y genera Markdown.
src/rag/ Capa de Inteligencia / QA Generación de embeddings vectoriales, indexación híbrida (BM25 para términos legales + búsqueda densa) y orquestación del LLM para responder preguntas.
tests/ Control de Calidad (QA) Pruebas automatizadas con pytest. Asegura que si cambias una función del parser, no rompas la extracción de artículos de normas anteriores.
docs/ Documentación del Software Documentación técnica para otros desarrolladores: cómo instalar el proyecto, cómo desplegarlo o cómo integrar la API.
bitacora/ Laboratorio de Aprendizaje Tu bitácora pedagógica interactiva personal (este documento HTML). No forma parte del software ejecutable.
requirements.txt Gestión de Dependencias (pip) Lista plana de librerías de Python instaladas vía PyPI (ej: pymupdf4llm, httpx, pydantic).
environment.yml Gestión de Entorno (Conda) Manifiesto reproducible que incluye tanto la versión del intérprete de Python como binarios C/C++ de bajo nivel del canal conda-forge.
README.md Carta de Presentación El archivo principal que muestra GitHub en la portada del repositorio: explica qué problema resuelve el proyecto, su arquitectura y cómo ejecutarlo.
.gitignore Seguridad y Limpieza en Git Evita que se suban a GitHub archivos de caché (__pycache__), PDFs gigantescos, secretos (claves API en .env) o archivos del sistema.

Navegación y Gestión de Rutas en UNIX

Antes de ejecutar cualquier comando de inicialización o creación de archivos, es crucial garantizar que la sesión de la terminal esté situada en el directorio de trabajo correcto.

# 1. Comprobar la ruta actual en la que está la sesión pwd
# 2. Navegar usando la tilde (~) como atajo a la raíz del usuario cd ~/Documents/ANTIGRAVITY/NORMA_SIID

Desglose anatómico:

Comando / Símbolo Tipo Función en el sistema
pwd Comando UNIX Acrónimo de Print Working Directory. Imprime la ruta absoluta del directorio donde se encuentra la shell.
cd Comando UNIX Acrónimo de Change Directory. Modifica el contexto de trabajo de la terminal hacia la ruta destino.
~ Atajo de Shell Representa la variable de entorno $HOME (en macOS: /Users/pablovaldes).
Ruta Absoluta vs Relativa Concepto Absoluta: Inicia con / o ~. Llega al destino sin importar en qué carpeta estés.
Relativa: No inicia con /. Depende de la carpeta en la que te encuentres parado en ese momento.

Entornos Aislados con Conda

En ingeniería de datos, mezclar librerías en el Python global de macOS causa el infierno de dependencias (dependency hell). Conda aísla intérpretes y librerías binarias C/C++ (esenciales para PDFs y ML).

# Comando completo para crear el entorno con nombre y versión fija conda create -n norma_siid python=3.11 -y

Desglose anatómico del comando:

Pieza del comando Categoría Explicación profunda
conda Comando Base Invocación al ejecutable de Anaconda/Miniconda en tu PATH.
create Subcomando Instruye a Conda a inicializar un entorno virgen sin heredar paquetes de otros entornos.
-n norma_siid Flag + Parámetro -n es la forma corta de --name.
Le dice a Conda que guarde el entorno de forma centralizada en ~/.conda/envs/norma_siid, en vez de obligarte a guardar una carpeta gigante en el directorio de tu proyecto.
python=3.11 Especificación Fija explícitamente el intérprete de Python en su versión 3.11.
¿Por qué 3.11? Las librerías de parsing de documentos y vector stores (como PyMuPDF, chromadb, etc.) dependen de extensiones compiladas en C++. Python 3.11 ofrece la máxima estabilidad y soporte precompilado (wheels) en macOS ARM (Apple Silicon).
-y Flag Booleano Abreviatura de --yes.
Le dice al gestor que asuma "Sí" a todas las preguntas interactivas (evita que la terminal se congele esperando que presiones Enter o escribas y para confirmar los paquetes base).
# Activar el entorno recién creado conda activate norma_siid

¿Qué altera `conda activate` internamente?

En sistemas UNIX, cuando escribes python, el sistema busca ese ejecutable en las carpetas listadas en la variable de entorno $PATH de izquierda a derecha. conda activate norma_siid antepone la ruta ~/.conda/envs/norma_siid/bin al inicio del $PATH. A partir de ese momento, cualquier comando pip install o ejecución de scripts corre dentro de tu burbuja aislada.

Esa carpeta contiene la base de datos de objetos (commits, árboles, blobs), la referencia HEAD (que apunta a la rama activa, por defecto main) y el área de preparación temporal (staging area / index).

Creación de Carpetas por Lotes: `mkdir` y Expansión de Rutas

Para no ejecutar mkdir diez veces seguidas, la shell Zsh permite crear jerarquías completas pasando múltiples rutas separadas por espacios, o usando expansión de llaves (brace expansion).

# Sintaxis ejecutada: múltiples rutas anidadas con flag -p y llaves mkdir -p data/{raw,processed,vault} src/{connectors,parsers,rag} tests docs bitacora

Desglose profundo de `mkdir -p`:

Elemento Categoría Función y Comportamiento
mkdir Comando UNIX Acrónimo de make directory. Crea nodos de tipo carpeta en el sistema de archivos.
-p Flag Crítico Abreviatura de --parents.
Cumple dos roles indispensables:
1. Creación jerárquica en cascada: Si escribes mkdir data/raw sin -p y la carpeta padre data/ no existe, el comando falla con el error: "No such file or directory". Con -p, el comando crea primero data/ y luego raw/ dentro de ella automáticamente.
2. Idempotencia: Si la carpeta ya existe, mkdir -p no arroja error ni sobreescribe nada; simplemente continúa silenciosamente.
{raw,processed,vault} Brace Expansion Zsh expande la llave multiplicando el prefijo data/ por cada elemento interno sin espacios, produciendo automáticamente: data/raw data/processed data/vault.

Creación de Archivos Vacíos: `touch` y Dotfiles

# Crear archivos raíz del proyecto en un solo paso touch requirements.txt README.md .gitignore environment.yml
# Crear archivos dentro de subcarpetas existentes touch data/raw/.gitkeep data/processed/.gitkeep data/vault/.gitkeep
Elemento Categoría Explicación
touch Comando UNIX Propósito original: Modificar los timestamps de un archivo.
Efecto útil: Si el archivo no existe, crea un nuevo archivo vacío (0 bytes).
.gitkeep Convención Git Git solo rastrea archivos (blobs), nunca directorios vacíos. Colocar un .gitkeep vacío obliga a Git a subir y conservar la carpeta en el repositorio.

Python Modular: Scripts vs Módulos vs Paquetes (`__init__.py`)

En software escalable, modular y testeable, es obligatorio estructurar el código como un Paquete de Python en lugar de scripts sueltos.

1. La Jerarquía Conceptual

Concepto ¿Qué es físicamente? ¿Cuál es su propósito?
Script Un archivo individual .py Diseñado para ser ejecutado directamente desde la terminal: python main.py. Contiene lógica lineal de principio a fin.
Módulo Cualquier archivo .py con funciones/clases Diseñado para ser reutilizado e importado por otros archivos: import extractor. No está pensado para ejecutarse de forma aislada.
Paquete (Package) Un directorio que agrupa múltiples módulos y un __init__.py Una biblioteca organizada con jerarquía de carpetas que encapsula una funcionalidad completa (como numpy, pandas o tu propio src).

2. ¿Para qué sirve el archivo `__init__.py`?

src/ ├── __init__.py # Le dice a Python: "src" es un paquete raíz importable ├── connectors/ │ ├── __init__.py # "connectors" es un sub-paquete │ └── bcch_siid.py # Módulo con la clase BCChDownloader └── parsers/ ├── __init__.py # "parsers" es un sub-paquete └── pdf_to_md.py # Módulo con la función parse_pdf()

Las 3 funciones críticas de `__init__.py`:

1. Marcador de Paquete Regular: Confirma explícitamente a Python y a los analizadores de código que la carpeta es código ejecutable e importable.
2. Código de inicialización: Lo que escribas dentro de __init__.py se ejecuta inmediatamente la primera vez que se importa el paquete.
3. Exposición de API pública limpia: Permite exponer imports directos como from src.connectors import BCChDownloader en lugar de rutas largas internas.

El error clásico que resuelve: `ModuleNotFoundError`

Si estás dentro de src/parsers/pdf_to_md.py e intentas hacer from src.connectors import BCChDownloader y ejecutas el archivo directo, Python por defecto sólo busca en parsers/ y falla. Al ser un paquete formal, las rutas absolutas son predecibles y válidas en todo el proyecto.

3. Decisión de Diseño: ¿Por qué estructurar como Paquete y no como Módulos Planos?

Criterio de Arquitectura Enfoque Módulos Planos (Archivos sueltos) Enfoque Paquete Modular (Estructura `src/`)
Escalabilidad (Nuevas Instituciones) Todo el código de descarga de BCCh, CMF y SII iría en un solo archivo monolítico de miles de líneas difícil de mantener. Submódulos independientes (src/connectors/bcch_siid.py, cmf.py) que heredan de una clase base común.
Aislamiento y Consumo de Memoria Al importar una función de scraping, Python cargaría en la memoria RAM todas las librerías pesadas de NLP y bases vectoriales. Carga granular: puedes importar solo src.connectors sin cargar librerías de ML, ahorrando RAM y tiempo de inicio.
Estrategia de Testing (QA) Probar una función de red requiere cargar y mockear dependencias no relacionadas con el parser. La carpeta tests/ replica fielmente la jerarquía del paquete (test_connectors.py, test_parsers.py).
Distribución y Reutilización Para usar tu código en otro proyecto o notebook, tendrías que copiar y pegar archivos `.py` manualmente. El paquete se vuelve instalable localmente vía pip install -e . y utilizable como cualquier librería profesional.

Selección y Diseño de Dependencias (`requirements.txt`)

En proyectos de nivel producción, cada dependencia debe estar estrictamente justificada. Instalar librerías innecesarias aumenta la superficie de ataque de seguridad, el peso de las imágenes Docker y el riesgo de incompatibilidades.

Lección de Terminal: ¿Qué es un Here-Doc (`cat << 'EOF' > archivo`)?

En la terminal, escribir archivos de varias líneas suele ser incómodo. Para resolverlo, UNIX inventó el Here-Document (Here-Doc):

cat << 'EOF' > requirements.txt
libreria>=1.0.0
EOF

¿Cómo lo interpreta la shell?
1. cat: Comando UNIX que lee y concatena texto.
2. << 'EOF': Le dice a Zsh: "espera que escriba texto libre hasta que veas la palabra clave EOF (End Of File)".
3. > requirements.txt: Redirige todo ese texto directamente al archivo, sobrescribiéndolo.
El error común: Si abres requirements.txt en VS Code y pegas ese bloque dentro del archivo, pip intentará instalar un paquete llamado "cat" y fallará. Es un comando de terminal, mientras que el archivo solo debe contener las librerías limpias.

# Comando para instalar el manifiesto de dependencias en el entorno activo pip install -r requirements.txt

Desglose anatómico del comando `pip install -r`:

Elemento Tipo Función y Comportamiento
pip Package Installer El gestor de paquetes estándar de Python que descarga e instala wheels desde el repositorio oficial PyPI.
install Subcomando Ordena descargar, resolver dependencias transitivas y compilar si es necesario.
-r requirements.txt Flag + Archivo -r es la forma corta de --requirement.
Instruye a pip a leer secuencialmente el archivo de texto y procesar cada línea como una especificación de paquete con sus versiones mínimas.

Matriz de Decisión de Dependencias:

Librería Capa en el Sistema ¿Por qué se seleccionó? (Justificación Técnica)
httpx>=0.27.0 Ingesta / Red Es el sucesor de la clásica requests. Soporta llamadas asíncronas nativas (async/await), HTTP/2 y configuración estricta de timeouts para no colgar la ejecución si la web del Banco Central no responde.
beautifulsoup4 + lxml Scraping HTML beautifulsoup4 provee la API de búsqueda en el árbol DOM del navegador. lxml es el motor C de bajo nivel ultra veloz que procesa el HTML del sitio web del SIID.
pymupdf4llm Parsing Documental Desarrollada por Artifex (creadores de MuPDF). A diferencia de pypdf o pdfplumber (que botan el texto plano perdiendo la estructura), pymupdf4llm detecta encabezados semánticos (#, ##), tablas en sintaxis Markdown y negritas, dejando el documento listo para LLMs y Obsidian.
pydantic>=2.7.0 Modelado de Datos Valida en tiempo de ejecución los esquemas de datos (metadatos de normas, artículos, fechas). Escrito en Rust (Pydantic V2), es hasta 20 veces más rápido que la versión anterior.
python-dotenv Configuración / Seg. Lee variables desde un archivo local .env. Evita la mala práctica de quemar API keys o rutas absolutas en el código fuente.
rich CLI / UX Genera barras de progreso animadas, tablas con colores y logs legibles en la terminal mientras se descargan o procesan documentos de gran tamaño.
pytest Testing (QA) Framework de pruebas estándar para verificar que las funciones de extracción y scraping no fallen ante cambios en los PDFs.
